# 配置管理指南

## 当前配置方式

仓库当前已经不再使用早期的“符号链接 + `docs/ai`”方案，而是直接让 VitePress 从项目根目录读取内容。

当前关键配置位于：

- `docs/.vitepress/config.ts`
- `docs/.vitepress/utils/sidebar.ts`
- `docs/.vitepress/components/NavigationCards.vue`
- `docs/public/404.html`

## 核心机制

### 1. 内容源

`docs/.vitepress/config.ts` 中通过：

```ts
srcDir: '../'
```

把项目根目录作为内容源。

### 2. 自动发现内容目录

`docs/.vitepress/utils/sidebar.ts` 会扫描项目根目录下的一级文件夹，并排除以下系统目录：

- `node_modules`
- `docs`
- `scripts`
- `.git`
- `.github`
- `dist`
- `.agent`
- `.claude`

剩余目录会被视为内容分区。

### 3. 自动生成侧边栏

每个内容分区内的 Markdown 文件和子目录会递归生成侧边栏。

### 4. 自动生成顶部导航

顶部导航不会为所有目录都生成入口，它只会读取：

- 一级内容目录
- 且该目录下必须存在至少一篇非 `index.md` 的根级 Markdown 文件

导航项默认会链接到该目录按字母序排序后的第一篇文章。

## 现在添加内容需要做什么

大多数情况下，只需要：

```bash
# 1. 新建内容或新目录
# 2. 编写 Markdown
# 3. 运行构建验证
npm run build
```

不再需要：

- `npm run check-config`
- `npm run fix-config`
- `scripts/copy-symlinks.js`
- 手工维护旧的目录映射表

## 仍然需要手工维护的地方

### 首页快捷卡片

首页的快捷入口来自：

```text
docs/.vitepress/components/NavigationCards.vue
```

它不是自动生成的。如果你想把新主题放到首页，需要手工添加或调整卡片。

### 固定文档分区

`docs/blog` 和 `docs/guide` 不是自动扫描根目录得到的，而是在 `sidebar.ts` 中单独写死入口。

## 维护建议

### 命名建议

- 尽量保持目录名稳定，不要频繁重命名
- 避免无意义的大小写变化
- 如无必要，避免在新目录名里使用空格

### 内容建议

- 新建一级目录时，至少放一篇根级正文 Markdown
- 建议保留 `index.md` 作为分类入口页
- 新增或调整内容后，先运行 `npm run build`

## 常见问题

### Q: 新建目录后侧边栏有了，但顶部导航没有？

A: 因为该目录只有子目录或只有 `index.md`，没有根级正文 Markdown。

### Q: 为什么链接路径看起来和目录名完全一致？

A: 因为当前实现直接使用真实目录名生成 URL，没有再做拼音化或别名映射。

### Q: 出现 404 时先看哪里？

A: 先检查：

1. 目录名和文件名是否符合预期路径
2. `docs/.vitepress/config.ts` 的 `base`
3. 首页卡片是否写了错误链接
4. `npm run build` 是否能通过
